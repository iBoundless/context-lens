# Context Lens

Локальный анализатор **новых исходящих запросов** OpenCode и Codex. Внешний вид основан на согласованном макете: стартовые слои, цветная карта, волны, категории, блоки и исходные данные.

## Текущее состояние

- Реализованы SQLite-хранилище, API с токеном, живые SSE-обновления, HTTP/SSE/WebSocket прокси, адаптер OpenCode 2.2.5, веб-интерфейс.
- Транспорт проверяется на локальных имитаторах без расходов на модели.
- Codex с подпиской **не объявляется поддержанным**. Неподтверждённый режим не блокирует остальные.
- [Матрица возможностей и источники](docs/capabilities.md).

## Установка и запуск на сервере

```bash
cd /path/to/context-lens
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m context_lens --port 18765
```

Сервис слушает только `127.0.0.1`. Порт можно изменить через `--port`. Эта команда запускает процесс в переднем плане. Для постоянной работы настройте пользовательский systemd unit по инструкции ниже. Если порт занят другим приложением, не останавливайте чужой процесс.

Приватные данные создаются в `.runtime/`: `capture.db` и `token`. Можно выбрать другой **отдельный приватный каталог** через `--state`. Не указывайте общие каталоги: права каталога будут установлены в 0700.

Показать приватную ссылку для входа:

```bash
.venv/bin/python -m context_lens --port 18765 --print-url
```

Токен находится во фрагменте ссылки, не в HTTP query. UI удаляет фрагмент после входа. Не публикуйте ссылку и не используйте токен сборщика как API-ключ модели.

### Desktop OpenCode по SSH

Для браузера на вашем компьютере нужен туннель, команда выполняется **на вашем компьютере**, не на сервере:

```bash
ssh -N -L 18765:127.0.0.1:18765 USER@SERVER
```

Замените `USER@SERVER` своим SSH-подключением. Откройте `http://127.0.0.1:18765/`, введите содержимое серверного `.runtime/token` или используйте приватную ссылку. Если локальный порт занят, можно использовать `-L 18766:127.0.0.1:18765`, открыв локальный порт 18766.

Наличие сессии в списке означает её обнаружение, **не включённую запись**. Включайте запись перед следующим запросом. Тот запрос, который впервые обнаружил сессию при выключенной записи, не восстанавливается из истории.

## Systemd

Пример пользовательского unit находится в `deploy/context-lens.service`. Перед установкой замените `/srv/projects/TestALL/context-lens` в unit на абсолютный путь к checkout и убедитесь, что зависимости установлены в `.venv`.

- Включите linger для пользователя, если сервис должен запускаться после перезагрузки без активной SSH-сессии: `sudo loginctl enable-linger "$USER"`.
- Автозапуск через `default.target` не зависит от OpenCode.
- `Restart=always`, задержка 3 секунды. Явный `systemctl stop` не вызывает автоматический запуск.
- Не более 10 попыток запуска за 60 секунд. При достижении лимита устраните причину и выполните `systemctl --user reset-failed context-lens.service`, затем start.
- `UMask=0077`, `NoNewPrivileges=yes`. Токен не передаётся в аргументах процесса или Environment.

Установите и включите unit от пользователя, который будет запускать сервис:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/context-lens.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now context-lens.service
```

Управление:

```bash
systemctl --user status context-lens.service
systemctl --user restart context-lens.service
systemctl --user stop context-lens.service
journalctl --user -u context-lens.service -n 50 --no-pager
```

Отключить сервис и его автозапуск:

```bash
systemctl --user disable --now context-lens.service
```

Linger действует на весь пользовательский менеджер, поэтому не выключайте его вслепую: он может требоваться другим пользовательским сервисам. При переносе проекта обновите пути в unit и выполните `systemctl --user daemon-reload` и restart.

## OpenCode 2.2.5

Следующий фрагмент нужно **добавить к существующему массиву plugins**, сохранив остальные настройки. Он не установлен автоматически:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "/path/to/context-lens/adapters/opencode",
      "options": {
        "endpoint": "http://127.0.0.1:18765",
        "token": "{file:/path/to/context-lens/.runtime/token}"
      }
    }
  ]
}
```

OpenCode V2 отслеживает изменения конфигурации. При необходимости используйте `/reload`, не требуется сбрасывать логин или перезапускать здоровый сервис. Вход по подписке и API-ключу не меняется: плагин наблюдает штатный транспорт.

Плагин не изменяет тела запросов, ответы, фреймы или заголовки. Проверка согласия перед запросом имеет таймаут 300 мс, сбой сборщика не отклоняет запрос модели. Фоновая очередь ограничена 1024 заданиями и бюджетом 32 MiB, одновременно работают 4 отправителя; каждое тело ограничено 8 MiB. Потери отмечаются отдельным gap-событием при восстановлении связи. Причины переполнения очереди, исчерпания бюджета и сетевого отказа различаются. При длительной недоступности сборщика или завершении процесса до восстановления точное число потерь неизвестно.

Сопоставление HTTP-ответов использует идентичность `Request`. Для WebSocket используется текущая последовательная попытка в паре session/kind; параллельные response.create в одном потоке пока не подтверждены. Хуки WS экспериментальные. Реальная применимость плагина должна проверяться на выбранной модели.

## Codex 0.164.0 с API-ключом

Прокси по умолчанию направляет только inference-маршруты к `https://api.openai.com/v1`. Другой **заранее выбранный** HTTPS-провайдер задаётся `--upstream https://provider.example/v1`. Адрес не берётся из запроса. Прокси не является HTTP CONNECT / TLS MITM и не устанавливает сертификаты.

Пример временного запуска Codex без изменения `~/.codex/config.toml`:

```bash
export CONTEXT_LENS_TOKEN="$(cat /path/to/context-lens/.runtime/token)"
# OPENAI_API_KEY уже должен быть задан безопасным способом; не вставляйте его в команду.
codex --no-daemon \
  -c 'model_provider="context_lens"' \
  -c 'model_providers.context_lens.name="Context Lens API"' \
  -c 'model_providers.context_lens.base_url="http://127.0.0.1:18765/proxy/codex"' \
  -c 'model_providers.context_lens.env_key="OPENAI_API_KEY"' \
  -c 'model_providers.context_lens.wire_api="responses"' \
  -c 'model_providers.context_lens.env_http_headers={"X-Context-Lens-Token"="CONTEXT_LENS_TOKEN"}' \
  -c 'model_providers.context_lens.supports_websockets=false' \
  -c 'features.enable_request_compression=false'
```

Этот пример выбирает API-провайдера, **не переводит подписку ChatGPT в API-доступ**. Существующий логин не удаляется. Имя модели оставьте доступное вашему API-провайдеру. Запуск реального запроса может быть платным; до согласования команда не выполнялась.

Codex передаёт `thread-id` и `session-id`; для изоляции потоков приоритет имеет `thread-id`. Для ручных проверок также поддерживается `X-Context-Lens-Session`. Без стабильного ID прокси отклонит запрос, а не смешает разные сессии. Для WS можно включить `supports_websockets=true` после проверки выбранного провайдера. Восстановление состояния по `previous_response_id` пока не выполняется: UI явно показывает `server-state-unknown`.

Запись сначала выключена: отправленный при выключенной записи запрос будет переслан, но его тело не сохранится. Включите запись обнаруженной сессии в UI перед следующим запросом.

### Отказ прокси

Если прокси остановлен, настроенный на него Codex получит ошибку подключения. Автоматического fail-open нет. Завершите временный запуск и запустите обычный `codex` без перечисленных override-параметров. Не меняйте логин и не удаляйте auth.json.

## Приватность и точность

- Заголовки авторизации, cookies, адреса с query и произвольные поля метаданных не сохраняются. Авторизация провайдера пересылается только фиксированному upstream.
- Сырые **тела** могут содержать секреты. Автоматического маскирования тела нет: оно нарушило бы точность захвата. Запись включается для конкретной сессии явно.
- Сервис привязан к loopback; браузерные запросы требуют same-origin, Host проверяется, API защищено случайным токеном. Локальный пользователь с доступом к токену получает доступ ко всем записанным сессиям. Это не многопользовательский сервис.
- Каталог данных 0700, файлы 0600. SQLite secure_delete включён, срок хранения 7 суток, очистка при старте и ежечасно. Это не шифрование и не гарантия удаления из резервных копий или снимков диска.
- Удаление сессии через UI выключает запись и удаляет её локальные записи. Активный адаптер может снова обнаружить ID, но запись останется выключенной.
- Токены по блокам: **эвристика `ceil(UTF-8 bytes / 4)`**, не точный модельный токенизатор. Usage провайдера показывается отдельно, сумма usage по попыткам - не размер окна контекста.
- Изображения, аудио, файлы и неизвестные модальности получают `?`, а не 0. Неразобранный протокол отмечается отдельно.
- Определение MCP по префиксу имени - эвристика. Навыки и AGENTS.md выделяются лишь при явных метаданных источника, а не по догадкам о содержимом. В обычном wire payload их происхождение может быть утрачено и тогда они остаются частью харнеса или результатов инструментов.
- Первая захваченная волна может быть серединой сессии. UI не обещает восстановить контекст до первого сообщения.
- Каждая физическая попытка показывается отдельно. Родительские связи субагентов и автоматическое объединение повторов пока не восстанавливаются.
- Список волн загружается окнами по 100 метаданных. Полные блоки выбранной волны загружаются отдельно, кеш браузера ограничен 4 волнами. Кнопка «Более ранние» позволяет просматривать предыдущие окна. Начальные слои и usage рассчитываются по всей сессии, не только по окну.
- WebSocket-прокси работает на уровне сообщений: ping/pong обрабатываются на каждом соединении, коды и причины закрытия пересылаются. Служебный response.interrupt не создаёт новую волну. Одновременные response.create в одном потоке помечаются association-unknown, а ответы не приписываются предположительно выбранному запросу.
- Ошибки SQLite не прерывают пересылку в прокси: счётчик ошибок виден в обзоре, gap сохраняется при восстановлении. При большом числе одновременно затронутых сессий точное соответствие потерь может быть недоступно. Это ограничение первой версии, не гарантия доставки всех событий.
- Тело более 8 MiB у плагина не сохраняется целиком, отображается gap. HTTP-прокси принимает до 16 MiB, сохраняет ответы до 8 MiB; усечение ответа обозначается в исходных данных.

## Тесты

```bash
.venv/bin/python -m unittest discover -s tests -v
node --test tests/*.test.mjs
```

Python-тесты используют временные SQLite-файлы и настоящие локальные HTTP/SSE/WS-серверы. Node-тесты проверяют контракт хуков, исходные потоки, выключенную запись, очередь и расчёты UI. Тесты не обращаются к реальным моделям.

Браузерная проверка проведена через встроенный браузер OpenCode: вход, пустое состояние, SSE, три искусственные волны, выбор волны, фильтр категории, раскрытие блока и HTML/XSS как текст. Тестовая сессия `TEST-ui-fixture` удаляется после проверки.
